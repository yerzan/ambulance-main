# LAST CALL: Emergency Transfer — правила для Claude Code

## Проєкт
Кооперативна first-person dark-comedy гра про транспортування NPC-пацієнтів швидкою.
Перша версія: **1–4 медики онлайн проти NPC-пацієнтів**. Керованого гравцем пацієнта (Patient Online) у цій версії НЕМАЄ.
Повний опис: `Docs/GDD/LAST_CALL_GDD_UA_v1_1.docx`.

## Технології
- Рушій: **Unity 6.7** + URP (точну версію рушія див. `ProjectSettings/ProjectVersion.txt`; не змінювати без дозволу).
- Мова: C#. Мережа: Netcode for GameObjects 2.x + Unity Multiplayer Services SDK (підтвердити в ADR-001).
- Git + Git LFS. Рішення по рушію: `Docs/Architecture/ADR-001-engine.md`.

## Жорсткі обмеження
- Камера ТІЛЬКИ first-person, включно зі швидкою. Жодних third-person чи зовнішніх камер авто.
- Host/server-authoritative. Клієнти надсилають наміри (ввід/запит), а не координати чи результат фізики.
- Кожна мережна дія перевіряє: хто викликає, чи має право, чи правильний стан матчу, чи не повторний запит.
- UI не викликає RPC напряму — тільки через gameplay service.
- Не додавати пакети/плагіни і не змінювати версію рушія, пакетів, input bindings та ProjectSettings без явного дозволу.
- Клінічні стани — не жарт; жодних реальних діагнозів, медичних процедур, дозувань чи реальних методів фіксації. Усе абстрактні ігрові механіки.
- Фізика й таймери не залежать від FPS.

## Архітектура
Presentation (UI/HUD/Camera/Audio/VFX) → Gameplay (Mission/Patient/Stretcher/Ambulance/Scoring) → Networking → Data (ScriptableObjects).
- Один клас — одна відповідальність; без величезних GameManager.
- Конфіги через ScriptableObjects / `[SerializeField]`, без дублювання значень у коді.
- Системи спілкуються через інтерфейси та події.

## Робочий процес
1. Складну задачу починай у Plan Mode: проаналізуй файли, ризики, запропонуй маленькі кроки. Нічого не редагуй до схвалення плану.
2. Одна задача — одна підсистема. Не змішуй Netcode, фізику нош, NPC і UI в одній зміні.
3. Реалізуй лише схвалений обсяг, додай EditMode/PlayMode тести.
4. Запусти compile/build і релевантні тести; звітуй точні результати.
5. Наприкінці: список змінених файлів, відомі обмеження, ручні кроки в редакторі.
Гілки: `feature/LC-xxx-коротка-назва` від `develop`; PR у `develop`.

## Definition of Done (кожна функція)
- Код компілюється без нових помилок і критичних warning.
- Є перевірка основного сценарію та щонайменше одного edge case.
- У мережевій функції клієнт не може змінити авторитетний стан без серверної перевірки.
- Контент/баланс налаштовується без редагування коду.
- Сцени/prefab перевірені в редакторі, Git diff переглянуто, обмеження записані.
